LaTeX Previews for Elfeed

Contents
Org’s new LaTeX preview system is out—time to celebrate! Not only does this mean that one can now enjoy reasonable previews without having to use a forked version of Org, but given that we are using the infinitely extensible text editor, this preview functionality can be used virtually everywhere. Let’s hack it into elfeed.

While its creator seems to disagree, I still believe that elfeed is by far the best feed reader in existence.
Certainly better than a vibecoded C++ GUI thing…
As RSS feeds are so static, it also feels like the ideal candidate to get a feeling for adapting org-latex-preview to other major modes.
Not that it makes much of a difference; the api as I see it is essentially plug-and-play.

The only function that we’ll need to get these previews working is org-latex-preview-place. It has two mandatory arguments, processing-type and entries. The latter is just a list of buffer positions (beg end) in which to find the LaTeX fragments, while the former sets the type of transformation you want to use.
dvisvgm, dvipng, or imagemagick, at the time of writing.
This means that the main thing we have to do is to collect all of the fragments: 
(defun elfeed-latex-preview ()
  "LaTeX preview the current elfeed buffer."
  (interactive)
  (save-excursion
    (with-syntax-table (copy-syntax-table)
      (modify-syntax-entry ?- ".") ; $x$-y is valid
      (when-let* ((entries
                   (cl-loop
                    for (_ re pos _) in org-latex-regexps
                    append (cl-loop
                            initially (goto-char (point-min))
                            while (re-search-forward re nil t)
                            collect (list (match-beginning pos)
                                          (match-end pos))))))
        (org-latex-preview-place 'dvisvgm entries)))))

The cl-loop code is so close to natural language that I feel like it should be obvious even if you’ve never seen such a loop expression. The only thing that’s slightly tricky is that Org doesn’t really recognise constructs of the form $x$-y as valid LaTeX—as far as I know because it conflicts with one of its million syntax rules. To hook this function into elfeed, we can simply check if the arXiv view is selected in either elfeed-search-mode or elfeed-show-mode, and then just call elfeed-latex-preview on the buffer: 
(defun elfeed-latex (&rest _)
  (when (or (string-match-p "arXiv" elfeed-search-filter)
            (and elfeed-show-entry
                 (memq 'arXiv (elfeed-entry-tags elfeed-show-entry))))
    (elfeed-latex-preview)))

(add-hook 'elfeed-search-update-hook #'elfeed-latex)
(add-hook 'elfeed-show-update-hook   #'elfeed-latex)
(advice-add 'elfeed-search-update-entry :after #'elfeed-latex)

As the names suggest, the two hooks are for when things change in elfeed-search-mode and elfeed-show-mode, respectively. The hooks for entering those major modes seem to run too early for LaTeX previewing to have any effect. The advice is needed since opening a feed entry with elfeed-search-show-entry does update and redraw its title (e.g., marking it read), but sadly elfeed bypasses the usual search-update machinery, and thus this doesn’t activate any of the required hooks.
